# 案例驱动的创作模板改造方案

日期：2026-10-27。状态：待确认方案；本文不代表功能已实现或模板已完成生成实测。

## 1. 产品方向

以后以“创作模板”为产品基本单位。一组模板包含一个明确主题、一套生成配方、多张案例和一组可选创作参数。当前三组分别成为三个模板；未来增加到 50 组，继续复用同一套页面和管理方式。

用户路径：看到效果 → 选择模板 → 上传照片 → 设置少量选项 → 创建任务 → 查看作品 → 再次创作。

“爆品”作为运营目标：全站指定一个主推模板，根据真实试用效果和使用数据调整，当前先以“把日常印成封面”为主推候选，不声称已经验证为爆品。

旧油画、水彩等模板从新用户的选项和默认运营列表中归档；历史任务、作品与历史提示词版本保留。现有上传、任务处理、积分、失败补偿和作品管理继续复用。

## 2. 当前问题与改造范围

已检查的实现：

- 案例展示读取 `content/case-templates/catalog.json` 和各组 `template.json`。
- 工作台仍使用旧风格目录；案例没有生成映射时，整页返回“正在准备”。
- 运营模板管理仍围绕旧风格，只有名称、单张图片、启用开关、默认提示词、固定规则及发布历史。
- 生成接口目前接收一张用户照片。原提示词中的双图输入要求尚未实际接通。
- 已有数据库提示词版本与管理员审计机制，可以作为改造基础。

需要一起改动：首页与案例详情的创作入口、工作台、运营模板管理、统一模板读取与任务校验，以及素材整理规范。单独替换页面文案不能解决问题。

## 3. 一组模板包含哪些内容

| 部分 | 主要内容 | 管理原则 |
| --- | --- | --- |
| 基础资料 | 稳定 ID、双语名称、简介、标签、适用照片、限制 | 名称可调整，ID 保持稳定 |
| 展示素材 | 封面、案例原照/成品配对、推荐顺序、来源身份 | 案例是模板的一对多内容，不是独立配方 |
| 生成配方 | 系统指令、参数定义、默认值、模型适配、画幅规则、可选参考图 | 每次发布保留不可变版本 |
| 运营配置 | 展示开关、创作开关、主推、排序 | 展示与创作分别控制 |
| 验证记录 | 测试照片、模型、配方版本、实际结果、问题 | 记录实际情况，不由上架开关推断 |

“展示案例图”“用户输入照片”“模型风格参考图”是不同用途。不会把整张采集截图自动传给模型，也不会把参考作者画面中的人物当作用户照片内容。

## 4. 用户界面

### 首页与案例墙

- 首页突出一个主推模板：原照/成品对比、简短效果说明、“用这个模板创作”。
- 其他模板作为精选入口；完整案例墙保留瀑布流、搜索与筛选。
- 案例详情显示所属模板，点击创作后传递模板 ID；登录后保留选择。
- 同一模板下的不同案例首先是效果参考，不会暗中变成不同生成配方。未来确有可重复变体时，再明确增加变体选项。
- 案例标明采集参考或本站实测；图库不会因为开放创作就改称本站生成效果。

### 工作台

- 从案例进入时直接显示所选模板，提供封面、小型案例预览、适用照片说明和“更换模板”。
- 直接进入工作台时，先选择模板；不再展示旧通用风格按钮。
- 桌面端左侧照片及预览，右侧模板说明、选项与创建按钮；手机端依次堆叠。
- 普通用户只填写该模板允许的选项。例如蓝纸封面的标题可自动生成或自行填写；画幅由模板约束，不开放会破坏效果的任意比例。
- 完整内部提示词留在服务端，由参数值组合；不再要求用户编辑整段提示词。可提供简短“补充要求”，有长度及适用范围限制。
- 模型由运营为模板配置默认值与兼容列表，日常流程不要求用户理解提供商；进阶入口仅显示兼容选项。
- 创建前展示实际积分消耗；沿用现有规则，不在此次改造中调整价格或积分金额。
- 某个模板不可用时，只限制该模板并说明原因，其他可用模板照常创建。

## 5. 运营管理模板页需要重做

改为有封面、状态和搜索的“创作模板”列表，能够处理 10—50 组；旧模板放入归档筛选。详情分为以下四部分：

| 区域 | 第一版功能 |
| --- | --- |
| 资料与案例 | 编辑主题、标签、适用照片；选择封面、调整案例顺序、记录来源 |
| 生成配方 | 编辑指令、配置参数与默认值、选择兼容模型、管理风格参考图 |
| 测试与发布 | 保存草稿、管理员试跑、查看实际结果、发布新版本、切回已有版本 |
| 上架与推广 | 分别控制案例展示和允许创作、设置排序、选择全站唯一主推 |

发布前检查必填资料、可用模型、参数合法性、必需参考图和测试记录。管理员试跑调用真实模型时应明确展示消耗，遵循现有扣费规则，不能因为位于后台就默认免费。

发布后修改先保存草稿，再发布新版本；旧任务始终使用提交时确定的版本。切回旧版本只改变新任务的选择，不改写旧版本内容。任务提交由服务端重新验证模板状态、版本、参数和模型，不能仅依靠界面隐藏。

测试质量与功能可用性分别记录。尚无实测就保留“未实测”，不会通过修改标记假装完成测试，也不会让单个模板的缺项关闭整个工作台。

## 6. 文件与后台的分工

继续使用文件收集，适合后续交给助手批量处理：

```text
content/case-templates/<template-id>/
  p.md                  # 原始提示词，保留原文
  prompt-v1.md          # 整理后的配方提案
  template.json         # 可校验的资料与输入配置
  originals/            # 原始素材，非公开
  references/           # 明确用于模型的参考素材
  processing-report.md  # 裁剪、缺项、处理记录
```

导出的公开图片继续放在 `public/cases/<template-id>/`；后续运营上传通过存储接口保存，不依赖向部署目录写文件。

文件是素材收集和导入来源；数据库发布记录是线上权威版本。第一批导入三组后，首页、案例页、工作台和后台读取同一模板服务。不能继续由文件决定首页、另一份硬编码目录决定工作台。

导入时显示新增/变更内容并校验；同 ID 重复导入不生成重复模板。重新导入更新草稿，不直接覆盖线上版本。后台修改不自动回写原始 `p.md`；需要留档时导出资料包。

模板版本需要保存完整生成配置快照，包含指令、参数、模型适配与参考素材版本。只保存一个会变化的文件路径不足以复现历史任务。

## 7. 当前三组如何接入

| 模板 | 第一版创作方式 | 上线前具体事项 |
| --- | --- | --- |
| 把日常印成封面 | 一张照片，固定方图，自动或自填短标题 | 检查人物、手部与文字排版；验证标题输入与实际模型表现 |
| 闯进漫画这一格 | 一张照片，黑白人物和彩色场景 | 原稿要求额外风格图：先整理成明确的单图文字配方并测试；保留原稿，不能称为原双图配方的已验证复现 |
| 今天有点小脾气 | 一张照片，马克笔涂鸦 | 同样先验证单图配方；协调色数与人物/宠物题材，移除新增他人署名的要求 |

建议第一版采用单图创作路线，降低用户操作成本。若第二、三组效果确实依赖参考图，则由运营配置固定风格参考图，并为该模板接入经过验证的多图模型；普通用户仍只需上传自己的照片。当前接口仅接单图，多图能力需要另行实现和验证，不能仅把“参考图二”写进提示词。

三组分别验证、分别开放。优先跑通蓝纸封面的完整创建链路；其他组的效果问题在各自模板中处理。

## 8. 落地顺序与验收

### 第一步：统一模板与恢复创作链路

建立统一模板服务与发布版本读取，迁入三组资料，归档旧入口。实现案例直达工作台、模板专属参数及服务端校验。沿用任务队列、作品库、登录与积分逻辑。

验收：由首页进入一个已开放模板，登录后选择不丢失；上传、提交、结果查看可完成；失败补偿、重复提交保护及历史作品正常。未开放模板不影响其他模板。

### 第二步：让运营可以持续上新

完成模板列表、资料/案例管理、草稿与发布、试跑及上架配置；先通过标准资料包导入支持批量上新。后台图片上传与导入均使用同一套校验与存储规则。

验收：新增第四组无需新增页面或修改前端风格枚举；后台修改主推、排序及可用状态后，各入口一致；提示词发布与切回版本不改变历史任务。

### 第三步：按真实效果选主推

补充三组的真实模型测试结果，以记录中的具体模型与版本为依据选择上线范围。后续记录模板浏览、进入创作、任务成功等事件，逐步形成主推选择依据。只展示已实际采集的统计，测试任务单独识别。

技术验收包括单元测试、任务与版本集成测试、桌面/手机端操作验证，以及仓库规定的 typecheck、lint、test。界面需同步更新 DESIGN.md 中仍停留在早期原型的描述。

## 9. 数据与实施边界

完整实现后台可新增模板、案例与参数配置，现有数据库字段不足，需要补充模板资料、案例关联及版本配置快照等结构。具体表结构在实施规格中确定，复用已有提示词发布、管理员权限和审计机制；通过新迁移执行，保留旧数据。

本方案尚未修改数据库 schema、依赖、计费规则、提示词、图片或页面代码。实施数据库变更前，按仓库 AGENTS.md 取得明确授权。真实模型实测的范围与消耗应在执行前确定，本文没有触发任何付费生成。

确认产品方向后，将本方案拆为实施规格，并同步修订 `CASE-TEMPLATE-PLAYBOOK.zh-CN.md`，作为之后每批素材整理与上新的执行依据。
