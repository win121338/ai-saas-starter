# 创作模板的日常操作

2026-10-27。运营入口：`/zh/admin/templates`。完整素材处理依据仍为 `CASE-TEMPLATE-PLAYBOOK.zh-CN.md`。

## 新增一组

1. 按素材规范保存 `p.md`、原件和来源记录，逐图裁剪、检查，填写 `template.json`。创建稳定模板 ID，不复用旧风格或其他模板 ID。
2. 整理 `generation-v1.json`：目录有 `refer.png` 就配置 `photo-with-reference` 和实际参考图描述；没有就使用 `single-photo` 并省略参考字段。注明真实输入要求、兼容模型、默认模型、画幅和可填写选项。没有真实模型记录时保持 `tested=false`。详细规则见执行规范第 13 节。
3. 本地生成并校验资料包：

   ```powershell
   node scripts/prepare-creative-package.mjs <模板ID>
   node scripts/prepare-creative-package.mjs <模板ID> --check
   ```

   生成器不修改数据库；首次生成的适用照片说明会沿用简介，需要检查并完善双语 `suitability`。已有资料包中的适用照片说明会保留。

4. 后台展开“导入新模板 / 更新草稿”，上传 `creative-template.json`。本地清单内的多组也可批量导入；重复 ID 更新草稿，不改线上内容。
5. 编辑资料、案例、配方。可上传新的公开案例成品及原照、调整顺序、选择封面与首页精选。采集参考与本站实测作品分别标记。
6. 保存草稿。需要实测时选择“保存并试跑”，上传测试照片并点击创建；界面显示实际积分消耗。保存试跑快照本身不扣分，提交图像任务才按现有规则扣分。
7. 检查实际结果，记录模型、配方版本、输入照片及问题。模拟图只证明任务链路，不能勾选真实模型实测。
8. 发布新版本后，在“上架与推广”分别开启案例展示和用户创作。需要主推时勾选全站唯一主推，设置排序并保存。

## 修改、切换版本与下架

### 每次只上架一组

新整理的“把自己画进独立漫画”“把生活印成复古海报”“掉进冷蓝漫画频道”已保存为本地后台草稿。

1. 进入 `/zh/admin/templates`，在左侧选择本次要上架的那一组。
2. 检查图片、封面、提示词、风格参考图及兼容模型，点击编辑区底部的“发布新版本”。首次发布生成 v1；只保存草稿不会公开显示。
3. 回到当前组的“上架与推广”，勾选“在案例墙展示”。如果同时开放用户生成，再勾选“允许用户创建任务”。
4. 设置排序数字并点击“保存上架设置”。这些操作只作用于当前组，不会批量上架其他草稿。
5. 只有需要替换首页主推时，才勾选“设为首页主推（全站仅一个）”。普通上架无需勾选。

首页顶部固定展示三个推荐位，主推优先，其余按模板排序选入；下方系列区最多显示六组，完整案例墙展示所有已发布且开启展示的组。因此顶部仍是三个推荐位，并不表示只能上架三组。调小排序数字可以将新组排到更前面。

当前上架单位是一组模板；组内案例图片随该组发布版本一起生效，尚无逐张图片的独立上下架开关。需要移除组内某张图片时，在草稿中移除该案例后发布新版本，旧任务所用版本保留。

- 资料、案例和配方先保存草稿，发布后才影响线上页面。任务始终使用创建时的版本。
- 在版本历史中启用旧版本，会一起恢复该版本的公开资料、案例与生成配置；当前草稿保留。
- 关闭“允许用户创建任务”后，该模板停止接受新任务；已创建任务继续处理。
- 关闭“在案例墙展示”只移除公开案例入口；如需完全停止新创作，同时关闭创作开关。隐藏前取消主推。
- 旧油画、水彩等资料在“旧风格归档”中查看，不接受新任务。
- 多人编辑有草稿冲突检查；提示已被修改时，重新加载后核对再保存。

## 文件与线上版本

`p.md` 是原稿，`prompt-v1.md` 是整理记录，`generation-v1.json` 是文件工作流中的生成配方稿（可选风格参考图），`creative-template.json` 是经过校验的导入包。

线上权威数据在数据库。后台修改不会回写原稿；“导出草稿资料包”可留档或迁入其他环境。重新运行本地资料包生成器会按文件稿重新生成案例与配方，不能拿它自动覆盖后台的未导出修改。

本地导入功能需要部署时包含已整理资料包。新上传的公开案例图通过图片存储与 `/template-media/` 访问，不向部署目录写文件。生产环境需要配置现有 Blob 存储；开发环境使用被 Git 忽略的 `.creative-media/`。

## 当前能力与验证边界

三组初始模板已发布为 v1，主推为蓝纸封面，均开放案例展示与创作。它们采用单图文字配方，真实图像模型的效果尚未付费实测；第二、三组不宣称已经复现原提示词的双图效果。

本版允许用户编辑模板定义的短文本选项，如封面标题。完整配方留在服务端。已支持可选风格参考图：有参考时图一是风格、图二是用户照片；无参考时只发送用户照片。新增三组使用双图配方，具体规则见案例执行规范第 13 节。

## 用户选择模型

工作台直接显示模型选择和“本次使用模型”，不折叠隐藏。用户明确选择后，工作台内切换模板不会清空模型；选择写入当前页面 URL，刷新可恢复。“再做一张”和失败后的重新编辑链接也会保留任务使用的模型。

若所选模型在新模板中不兼容、未配置或被停用，保留原选择并提示用户明确选择其他模型，禁止静默回落到模板默认值。后端也会再次校验模型和可用状态；提供商请求失败会保留原模型并进入失败/补偿流程，不自动改用另一个模型。

2026-10-27 模型选择修复验证：219 项单元与集成测试通过；回归覆盖请求模型入库、Seedream 拒绝后的模型保留，以及浏览器切换模板、刷新、再创作和不可用模型阻止提交。测试使用隔离数据库与模拟图像服务，不重跑现有付费任务。

## Seedream 模型开通诊断

2026-10-27 使用项目当前配置做了不生成图片的诊断：官方模型列表请求返回 200，并包含 `doubao-seedream-5-0-flash-260915`；向生成接口发送缺少图片/提示词且尺寸为无效 `0x0` 的诊断请求，返回 HTTP 404 / `ModelNotOpen`。响应明确表示服务账号尚未开通该模型。模型目录存在、密钥能完成基本认证，不代表该模型已在账号下开通。

处理入口为 [火山方舟开通管理](https://console.volcengine.com/ark/region:ark+cn-beijing/openManagement)。使用当前 `ARK_API_KEY` 所属账号，找到上述完整模型 ID 并开通。具体开通条款、计费和账号权限由控制台显示；应用不自动开通服务，也不自动重跑旧任务。

依据：[官方错误码](https://docs.volcengine.com/docs/ark/error-codes?lang=zh&redirect=1)、[官方 Seedream 5.0 模型说明](https://docs.volcengine.com/docs/ark/seedream-5-0-pro?lang=zh)。

代码现在仅提取错误码并转换为固定分类，不记录或展示可能含账号信息、密钥或图片内容的原始错误消息。新任务分别记录模型未开通、鉴权失败、无访问权限、模型/接入点不可访问及账号状态异常；原有历史失败码保留。确定拒绝的请求继续退分，不更换模型或自动重复提交。

本轮类型检查、Lint 与 228 项单元/集成测试通过，覆盖未开通错误的分类、中文提示、退分幂等和保留所选模型。诊断未生成图片或重跑现有任务。

## 用户选择画幅

所有用户均可选择 1:1、3:4、4:3、4:5、5:4、2:3、3:2、9:16、16:9 或原图比例，不按套餐设限。后台的输出比例是默认值，用户选择优先；切换模板保留当前选择，“再做一张”也带回原有比例。

上传预览始终按原照片比例完整显示，切换输出画幅不会改变或裁剪原图。提交时原照片仅做方向校正、去元数据和必要的等比缩小，不按输出比例裁剪；保存和发送给模型的照片均保留完整画面。比例、选项和输出画幅设置单独保存，生成请求使用各模型支持的尺寸参数，仅在保存成品时按请求比例居中校正，不拉伸图片。这里选择的是输出画幅比例，实际像素尺寸由模型决定。此前已裁剪保存的旧任务无法恢复缺失内容，需要重新上传原照片。

旧发布版本不改写；只有带新画幅设置的任务才启用画幅优先的指令组合。新任务不再因原稿中“方图”等描述而强制返回 1:1，历史任务按原规则读取。

接口实现依据：[千问图像 API](https://help.aliyun.com/en/model-studio/qwen-image-generation-and-editing-api-reference)、[万相图像 API](https://help.aliyun.com/en/model-studio/wan-image-generation-and-editing-api-reference)、[Seedream 图像 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh&redirect=1)、[Kontext API](https://fal.ai/models/fal-ai/flux-pro/kontext/api)。Kontext 仅提供固定原生比例列表；其他常用比例使用接近的原生画幅生成，再按用户选择校正成品。

本次画幅调整验证：类型检查、Lint、217 项单元与集成测试通过；工作台 4 项浏览器检查与后台发布检查均通过，覆盖普通用户选择、切换模板保留比例、裁剪预览、生成成品比例及再创作链接。仍使用隔离测试库和模拟模型，没有消耗现有用户积分。

此轮没有调整积分金额、套餐、支付规则或已有依赖。数据库结构与初始资料通过新迁移导入，原有历史任务、提示词版本和素材原件保留。
