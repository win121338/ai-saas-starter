# 运营后台：首版实现与后续计划

首版后台位于 `/admin`（中文入口 `/zh/admin`）。独立校验管理员权限；普通登录用户访问会得到 404。当前本地数据库已经应用 `0006` 迁移。

## 初始管理员开通

1. 先注册或登录一个确定由站长控制的账号。
2. 在本地数据库查找该账号的 `users.id`：`SELECT id, email FROM users;`。
3. 在不会提交到 Git 的 `.env` 中设置 `ADMIN_BOOTSTRAP_USER_ID=<该账号的 id>`，重启开发服务，然后访问 `/admin`。本地开发库目前只有一个账号，已自动将其 ID 写入本机 `.env`；正式部署时需要在部署平台单独设置此变量。
4. 初始管理员可以在“会员”页按现有用户邮箱授予额外管理员权限。授权会写入 `admin_members` 和操作日志。不要将该环境变量设置为邮箱或公开给浏览器。

## 第一版范围

| 模块       | 首版能力                                                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 会员管理   | 按邮箱搜索，查看注册时间、订阅状态、积分缓存余额、任务数；初始管理员可以给现有账号授权。                                        |
| 订单与订阅 | 只读展示 Stripe 最近 50 笔付款中属于本站用户的记录及退款金额，以及最近 50 条本地订阅同步状态。Stripe 未配置或不可用时给出说明。 |
| 模板管理   | 管理风格名称、案例图 HTTPS 地址、启用状态；发布默认提示词与固定风格规则的新版本。新任务使用新版本，旧任务和重试保持原版本。     |
| 系统参数   | 设置工作台公告、逐个启用/停用图像模型。模型停用在提交动作里再次检查；API Key 仍只放服务端环境变量。                             |
| 任务与审计 | 筛选最近 100 个生成任务，查看状态与失败码；查看最近 100 条管理员操作。用户原图与结果不在后台展示。                              |

## 实施顺序与边界

1. 每个后台页面和修改动作都在服务端重新检查权限，操作审计与修改同事务提交。后台只管理明确列出的非机密参数。
2. 模板版本只新增不修改，用户任务记录所选版本和单次修改的提示词。管理员停用风格或模型只阻止新任务，不中断已提交任务。
3. 人工退款、补偿积分、封禁账号、权限撤销和批量处理留待下一轮设计。积分仍只能通过 `src/lib/credits/` 追加补偿流水；订单与订阅状态仍由既有支付同步流程维护，不能直接在后台改表。

首版不加入任意 SQL、明文密钥管理、直接修改积分余额或任意改写订单状态。Stripe 付款页只是最近记录窗口，不是完整账务报表；供应商真实成本也尚未入库。会员封禁、退款权限、模板审核流程和正式套餐价格，需要上线支付方案确定后再定。
