## 1. 建议采用的方案

保留 ai-saas-starter 的账号、数据库、积分账本与测试基础，改造成面向海外用户的「上传照片，选择艺术风格，一键生成作品」产品。

- **产品结构参考 ImgGen**：营销首页、风格案例、价格页，以及登录后的生成工作台。
- **视觉优先参考 PipNow**：近黑背景、暖橙色主按钮、白色标题、克制的发光与圆角卡片。图片作品是视觉主体。
- **首发英文**：页面和邮件使用英文；开发文档使用中文。文案集中管理，后续再扩展语言。
- **首期集中做图转图**：用户不必学习提示词；你的预设提示词在服务端组合。
- **先接一个图像供应商、一个支付渠道**：保留替换接口，避免首期同时维护多套服务。
- **支付以 Creem 为待核实的首选**：适配你的大陆个人／个体户情况；账号与业务审核通过后才开启真实收款。

工作名称暂用 **Artora**，仅作为原型占位，不代表域名、商标或名称可用性已经核验。品牌可以集中替换。

**2026-10-22 实施补充：**用户确认了方案 A 和 P1，并明确要求案例图片由其后续根据专属提示词效果配置。P1 因此只提供统一的案例位置与清楚的占位说明，没有加入通用生成图作为产品效果证明。

## 3. 首期用户与功能范围

### 3.1 核心体验

用户从一张人像、宠物或风景照片出发，选择喜欢的艺术效果，生成可下载的作品。首期每次上传一张、输出一张，默认保留原图比例；只有模型实际支持的尺寸才会出现在界面中。

核心流程：

```text
首页／风格详情
  → 选择风格
  → 登录／注册（保留选择的风格）
  → 上传照片并预览
  → 查看本次所需积分
  → 提交生成
  → 等待／查看任务状态
  → 原图与结果对比
  → 下载／再次生成／在作品库查看
```

建议首发 6 个风格：油画、水彩、铅笔素描、手绘动漫、复古海报、黏土质感。最终上线的风格以实际模型测试为准，不用未经验证的案例宣传效果。

你的预设提示词是产品核心。开发阶段可以使用明确标记的演示预设；正式上线前替换为经过测试的正式版本。

### 3.2 首期包含

- 营销首页、风格目录、6 个风格详情页、价格页、FAQ、联系入口。
- 邮箱注册／验证／登录／找回密码；配置完成后开启 Google 登录。
- 拖拽或选择图片、预览、替换、风格选择、积分确认、生成状态。
- 结果查看、前后对比、下载、重新生成、分页作品库、删除作品。
- 积分余额和流水、购买积分包、月订阅、取消续订入口。
- 英文隐私政策、服务条款、退款说明；具体主体和政策在上线前补齐。
- 基础 SEO、访问与转化统计、错误与生成成本监测。

### 3.3 后续迭代

视频生成、多人协作、批量任务、公开社区、用户分享链接、多模型选择、完整运营后台、优惠券与推广返佣、年付套餐、多语言、积分到期机制放到后续。首期通过代码配置管理风格，不先做复杂管理后台。

## 4. 视觉方向与页面设计

### 4.1 参考站观察与建议

2026-10-22 已实际查看两个参考站首页：

| 参考                              | 看到的特点                                                   | 在本项目中的用途                             |
| --------------------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| [ImgGen](https://www.imggen.org/) | 深紫背景、紫粉渐变主按钮、黄色导航按钮、大标题、横向效果案例 | 参考图片工具的内容组织、案例展示与工作台入口 |

备选方案 B：更接近 ImgGen 的深紫背景与紫粉强调色。页面结构和功能不变，只调整设计变量及视觉细节。

| 边框           | `#2C3342`               |
| 主标题／正文   | `#F4F6FA`               |

设计细则：桌面内容宽约 1200px；卡片圆角 16–24px；轻边框；只在首屏和主按钮使用少量光晕。首发统一深色主题，暂不同时维护两套主题。字体优先复用已有 Instrument Sans；使用现有 Lucide 图标，不新增动画库。

### 4.2 首页布局

1. **顶部导航**：品牌、Styles、How it works、Pricing、Sign in、Create art。
2. **首屏**：简短英文主标题，例如 “Turn your photos into art.”；一行说明；主按钮；一组真实的原图／作品对比。
3. **风格展示**：6 个大图卡片，点击进入详情或预选风格进入工作台。
4. **三步说明**：Upload a photo → Choose a style → Create your artwork。
5. **效果案例**：人像、宠物、风景，展示不同输入的真实效果。
6. **价格摘要**：积分包和订阅入口；未定价时只用于本地设计预览。
7. **FAQ**：耗时、积分、失败返还、图片保留、下载、取消订阅。
8. **底部转化与页脚**：进入工作台、联系、法律页。

不复制参考站品牌、图片或用户评价；示例图片需有使用授权。演示素材必须可识别，不编造用户规模、生成速度或“全部可商用”等承诺。

```text

│ 品牌              Create / My creations       积分 账号 │
├───────────────────┬─────────────────────────────────┤
```

手机端改成纵向流程：上传 → 风格 → 生成 → 结果，提交按钮和消耗提示易于触达。上传失败、余额不足、服务繁忙、处理中、返还处理中均有独立状态；不显示虚构进度百分比。

## 6. 图转图与提示词实现方案

### 6.1 风格配置分离

- **公开配置**：风格 ID、slug、名称、简介、封面、展示顺序、支持的输入说明。
- **服务端配置**：完整提示词模板、负面提示词（模型支持时）、模型参数、版本号、成本映射。
- 客户端只提交图片引用和风格 ID；服务端重新校验并确定最终提示词、模型和扣费。
- 不把封装提示词发送到客户端 bundle、页面序列化数据、历史列表或日志中。
- 历史任务记录风格版本，方便定位效果变化；第一期不开放自由提示词输入。
- 服务端封装保护的是网站客户端访问边界，模型供应商仍需要接收生成提示词。

### 6.2 图片上传与存储

建议首版接受 JPEG、PNG、WebP；单张上限暂定 10MB，像素上限按模型和服务端资源确定。服务端校验文件实际类型与大小，处理方向信息，必要时缩放并移除 EXIF。

生产方案先评估现有 Vercel Blob 的私有访问能力，满足要求时优先复用；如果成本或授权方式不适合，再选择 S3 兼容私有存储。不能沿用当前 `access: "public"` 存放用户原图。

上传和读取都绑定用户权限；模型需要读取原图时使用受限有效期地址或供应商支持的文件上传。限制上传速率与存储配额，防止未生成的文件长期堆积。下载输出只接受已校验的供应商结果地址，限制协议、域名、重定向和大小。

拟定保留策略：输入原图在任务终结 24 小时后清理；生成结果默认保留 30 天，允许用户提前删除。处理中的输入不被清理任务误删。原图过期后，历史页仍可下载结果，但再次生成需要重新上传。最终期限需要结合成本和用户体验确认，并与页面说明一致。

### 6.3 图像供应商选择

当前可比较千问 Image 2.1 Turbo、Qwen-Image 3.0 Pro、万相 2.7 Pro／标准版和 Seedream 5.0 Flash。正式供应商组合和销售价格要根据同一批照片的质量、速度与实际费用确定。fal、OpenAI 等海外模型留待后续接入。不能用普通文生图接口冒充图转图。

接入前使用同一组授权样本评测：人物相似度、构图保留、风格效果、失败率、平均耗时和长尾耗时、单次总成本。建议至少覆盖人像／宠物／风景各 5 张。确认供应商的数据保留和商业使用条件后再形成页面承诺。

### 6.4 任务与积分流程

```text
登录与输入校验
  → 创建持久化任务（用户 + 请求幂等键）
  → 通过现有账本原子扣积分
  → 后台提交图像任务
  → 保存供应商任务 ID
  → 回调／后台查询状态
  → 保存结果到本站存储
  → 标记完成并允许下载

确定失败 → 幂等返还积分 → 展示返还结果
结果不明／网络超时 → 查询与对账 → 确认后完成或返还
```

不能让任务只依赖浏览器持续打开，也不能在 Web 请求结束后启动无人托管的异步函数。首个真实付费版本必须包含持久化任务记录、后台执行／恢复机制和超时对账。具体使用托管任务服务还是独立 worker，在模型和部署环境确定后写入功能规格。

关键约束：

- 重复点击、请求重放不能重复扣费；不同主动生成请求可以分别扣费。
- 供应商任务提交结果不明时，先查询或进入待对账状态，不盲目重提产生双倍成本。
- 前端轮询超时不等于供应商生成失败，不立即返还或自动重复生成。
- 结果已生成但存储失败时优先重试保存，避免重复付费生成。
- 返还失败显示处理中并进入重试／告警，不能直接宣称已到账。
- 账本继续由 `src/lib/credits/` 独占写入，保留整数金额、整数积分和追加式流水。

## 7. 支付与商业规则

### 7.1 渠道建议

Creem 官方支持国家列表包含 China，但实际收款还要完成身份／主体核验、结算账号配置和平台审核。支持国家不等于你的个人或个体户账户必然获批。来源：[支持国家](https://docs.creem.io/merchant-of-record/supported-countries)、[收款账户与审核流程](https://docs.creem.io/merchant-of-record/finance/payout-accounts)，核对日期 2026-10-22。

因此采用「Creem 适配优先、账号审核作为真实收款前置条件」的方案。Paddle 留作备选，届时重新核实主体资格和实际接口；首期不同时接两家。

### 7.2 接入范围

1. 商品与套餐配置：本站套餐映射平台商品 ID，测试和生产配置分离。
2. 创建 Checkout：服务端校验用户和商品，只接受本站允许的套餐。
3. Webhook：按供应商规则验证签名，记录事件并幂等处理。
4. 积分包：确认支付成功后发放积分，不能根据浏览器成功跳转直接充值。
5. 订阅：首付／续费成功后按实际支付周期发放，取消与到期同步权益。
6. 客户门户：管理支付方式、查看账单、取消续订。
7. 退款与争议：保留事件审计，定义已消费积分的处理规则；不能为了回收积分破坏余额非负约束。
8. 账号删除：同时处理订阅取消、图片清理与必要账务记录，审核现有级联删除行为。

现有代码对 Stripe 的依赖还存在于注册创建客户、删除账号、环境变量生产校验、订阅表字段和账单展示中。这些必须一起梳理，不能只替换支付按钮。

订阅状态继续只有统一同步模块可以写入。支付适配重构时同步更新仓库说明中的 Stripe 专属约定，保留验签、幂等和账本规则。

### 7.3 套餐与成本

建议首发「单次积分包 + 两档月订阅」。暂不开放年付、无限生成或每日免费赠送。试用额度待成本和防滥用方案确定后再决定。

原模板中的 `$9 / $29`、每次 1 积分、注册 10 积分属于示例值，**不视为本产品已批准的商业规则**。真实收款前统一替换并校验价格页、Checkout 和到账积分一致。

定价测算至少包括：

```text
每张交付成本 =（生成调用费用 + 失败／重试费用 + 存储与流量费用）/ 成功交付张数
套餐贡献 = 实收金额 - 支付与结算费用 - 实际交付成本 - 退款／争议准备
```

建议首期积分不设到期时间，延续现有账本能力；订阅取消后停止未来续费与发放，已到账积分继续可用。退款扣回、免费额度和最终售价仍需正式确认，不能在未实现时宣传另一套规则。
